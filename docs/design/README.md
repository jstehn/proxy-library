# Design docs

The design docs are the record of **why** each feature was built, one doc per feature, written before
it. The product rules that still hold are collected, one page per responsibility, in
[../modules/README.md](../modules/README.md); read those to learn how something works today. Read a
design doc when you need the reasoning behind a rule, or its tables, sketches and test plan.

Superseded docs are in [archive/](archive/): every rule in them (their Invariants and Decisions
sections) is on a `docs/modules/` page. A doc marked **superseded in part** stays here because
something in it is not on a page yet, or a decision about it is open (its Status line says which). Start a
new design doc from [TEMPLATE.md](TEMPLATE.md) and name the module page it changes.

## Numbering

Don't renumber: lessons, ADRs and code comments cite docs by number (`pnpm docs:citations` checks
that every citation points at a live or archived doc). **47 and 48 each have two docs** (47: rating
tuning and swaps, public deck links; 48: copy a shared deck, social profiles and friends). **50, 62
and 63 do not exist**, and the numbering starts at 02.
